## INT-001 — إسناد الخلفية والعقود والموقع العام

- التاريخ: 2026-11-15.
- الحالة: مفتوح للتخطيط؛ لا يمنع أعمال الواجهات المستقلة.
- المصدر: مراجعة القسم 12 وAD-FR-035 من وثيقة المتطلبات.
- المنفذ: غير مسند؛ لا يوجد مطور ثالث مفترض.
- المطلوب: إسناد مهام `supabase/` و`contracts/` وإعدادات الويب المشتركة والموقع العام صراحة لأحد المطورين قبل تنفيذها، مع فصل مهام الواجهتين.
- معيار الإغلاق: تسجيل الإسناد والمسارات ومعايير القبول والمهام التابعة في سجل التقدم، وتحديث قرار التنسيق عند تحديد المالك الدائم.
- لا يوجد عقد API تنفيذي معتمد حاليًا؛ نموذج البيانات في SRS مرجع متطلبات وليس دليلًا على وجود خدمة منشورة.

## INT-002 — تسليم احتياجات ربط تصميم الجوال بالخدمات

- التاريخ والجانب الطالب: 2026-11-15 — Asia/Riyadh؛ MOBILE.
- المهمة: MOBILE-UX-FIGMA-PLAN؛ الحالة مفتوح، غير مسند للتنفيذ الخلفي.
- السبب: ملف Figma يعرض بيانات وحالات تجريبية؛ لا يثبت وجود خدمة منشورة أو عقد تنفيذي معتمد. لا تُنشأ عقود API من التصميم وحده.
- المدخلات المطلوبة عند إسناد الربط: الإعدادات المنشورة للحدود والقوائم، صلاحيات الحساب، حالات الإعلان والوسائط، الموافقات على التواصل، أهلية التجديد والتقييم، نتائج التوثيق الموثوقة، فئات الإشعارات وإتاحة الخرائط.
- المخرجات والسلوك المطلوب: حفظ واستعادة وتأكيد خادم وأخطاء حقلية وحالات انتظار/رفض/إخفاء وانقطاع اتصال، دون نجاح أو شارة توثيق قبل تحقق موثوق. مراجعة حالات سحب آخر موافقة تواصل مع الخلفية وفق AD-FR-014 دون اختلاق حالة جديدة للعقد.
- نطاق الإسناد المستقبلي: تحدد ملفات supabase/ وcontracts/ صراحة في مهمة مستقلة لأحد المطورين. لا تعديل لهذه الملفات في مهمة التصميم الحالية.
- التوافق: الجوال والويب يستهلكان الحالات والقوائم نفسها؛ لا تغييرات كاسرة أو ترحيل ضمن تسليم التصميم. تدرس العقود والإصدارات والترحيلات عند الإسناد الفعلي.
- معايير القبول: اجتياز معايير SRS المرتبطة بكل رحلة، والتحقق من جانب الجوال والخادم قبل وصفها متكاملة؛ اختبار إعدادات الحدود والصلاحيات والرفض والتكرار وخصوصية الوسائط والوثائق.
- ما يمكن متابعته مستقلًا: المراجعة البصرية وربط النموذج ومواصفات الإتاحة والتسليم داخل Figma.
