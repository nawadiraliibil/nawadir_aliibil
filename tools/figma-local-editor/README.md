# محرر نسخة العمل المحلي لـ Figma Desktop على Windows

إضافة تطوير مستقلة لصاحب مهمة MOBILE-FIGMA-LOCAL-001. تعمل على تصميم موجود عبر **Figma Plugin API** مباشرة، دون حزم أو بناء أو خادم أو Figma MCP أو REST أو طلبات شبكة. يمنع [manifest.json](./manifest.json) الاتصال (`allowedDomains: ["none"]`)، وتمنعه سياسة واجهة الإضافة أيضًا. الملفات تنتقل يدويًا بين Figma وCodex عبر القرص.

## الاستيراد مرة واحدة

1. افتح **نسخة عمل مستقلة** من التصميم في تطبيق Figma Desktop على Windows.
2. اختر `Plugins → Development → Import plugin from manifest` وحدد [manifest.json](./manifest.json) من هذا المجلد. لا تحتاج Node لتشغيل الإضافة.
3. شغّل «محرر نسخة العمل المحلي — Codex» من `Plugins → Development`.
4. افتح قسم «هوية نسخة العمل»، واضغط **هوية جديدة لنسخة العمل** مرة واحدة، ثم وافق على الرسالة. تحفظ الهوية في `figma.root` عبر `setPluginData`، ولا تحفظ بيانات تصميم خارج الملف.
5. ثبّت الخطوط التي يستخدمها التصميم، ومنها خط العربية الفعلي؛ لا تستبدل الإضافة الخطوط تلقائيًا.

الهوية ثابتة عبر الجلسات. عند إنشاء نسخة جديدة من ملف سبق تهيئته **أنشئ هوية جديدة في النسخة الجديدة قبل التصدير**: نسخ Figma قد ينسخ pluginData أيضًا. لا تستطيع Plugin API ضمان تمييز ملفين منسوخين تلقائيًا حين لا تتيح `figma.fileKey`؛ لهذا خطوة التهيئة صريحة وليست فحصًا أمنيًا لإثبات هوية الملف. عند إتاحة `fileKey` تستخدمه الإضافة كحارس إضافي خلال الجلسة. بعد التهيئة، ملف بهوية مختلفة مرفوض. زر الهوية يبطل التصدير والمعاينة الحاليين؛ لا تضغطه عند كل تعديل.

## دورة كل تعديل مع Codex

1. حدد إطارًا أو طبقات في نسخة العمل. اضغط **تصدير التحديد JSON** واحفظ الملف. تُضمّن الطبقات الفرعية أيضًا دون مضاعفة العنصر عند تحديده مع أبيه.
2. اترك الإضافة مفتوحة، وعلى صفحة التصدير نفسها، وأعط Codex الملف ومسار هذا الدليل وطلبًا محددًا، مثل:

   > الجانب MOBILE، ضمن مجلد الإضافة فقط: اقرأ README وتصدير التحديد المرفق. أنشئ ملف codex-figma-patch بإصدار 1 يغير عنوان القائمة إلى «أحدث إعلانات الإبل» والمسافة بين عناصرها إلى 20. انسخ workspaceId وexportId وbefore وbeforeBindings حرفيًا من التصدير؛ لا تختلق معرفات، ولا تعدّل ارتباطات المتغيرات أو المكونات. سلّم ملف JSON فقط، ولا تستخدم Figma MCP أو REST أو شبكة.

3. اضغط **استيراد تعديلات ومعاينتها** واختر ملف Codex. يعرض الجدول اسم العنصر ومعرّفه والخاصية والقيمتين والارتباطات وحالة كل عملية.
4. عند وجود أي تعارض، تُمنع الدفعة كلها. أعد التصدير واطلب من Codex إنشاء ملف جديد. لا تعالج التعارض بتغيير `before` يدويًا لتجاوز الحماية.
5. اضغط **تطبيق** بعد مراجعة الجدول. العمليات الموسومة «متجاوز» لا تطبق؛ الباقي يطبق كدفعة واحدة. يعاد فحص كل العناصر بعد تحميل الخطوط وقبل الكتابة.
6. للتراجع استخدم `Ctrl+Z` مرة واحدة داخل لوحة تصميم Figma؛ إذا كان التركيز داخل نافذة الإضافة أعده أولًا إلى اللوحة. يمكن التراجع عن دفعات متعاقبة بخطوة لكل دفعة.
7. **صدّر مجددًا بعد كل دفعة**؛ نجاح التطبيق يبطل اللقطة السابقة. إغلاق الإضافة أو إعادة تحميلها يمسح آخر تصدير ومعاينة من الذاكرة، لذلك يلزم تصدير جديد في الجلسة التالية. الهوية المحفوظة في الملف تبقى.

اختلاف ترتيب مفاتيح JSON لا يسبب تعارضًا. تغيير العنصر أو اسمه أو أبيه أو قياسه أو تنسيقه أو ارتباطاته بعد التصدير قد يسبب تعارضًا حتى لو لم تتغير الخاصية المستهدفة؛ هذا فحص متحفظ لحماية التصميم. تغيير الصفحة يمنع التطبيق حتى تعود إلى صفحة التصدير.

## صيغة التصدير

[selection.example.json](./examples/selection.example.json) مثال **مختصر توضيحي**؛ التصدير الحقيقي يضم حقولًا وخصائص أكثر. لا تستورده باعتباره ملف تعديلات.

| الحقل | المعنى |
|---|---|
| `schema`, `version` | `codex-figma-selection` و`1` |
| `workspaceId`, `exportId` | هوية النسخة ومعرّف لقطة التصدير؛ يجب نسخهما إلى ملف التعديلات |
| `fileKey`, `pageId`, `exportedAt` | مفتاح Figma عند إتاحته، صفحة المصدر، وقت UTC بصيغة ISO |
| `selection` | معرفات جذور التحديد |
| `nodes[]` | العنصر وكل الطبقات الفرعية؛ `id/name/type/parentId/children/path` تحفظ العلاقات والسياق |
| `nodes[].properties` | النص، المحاذاة، الطلاءات، Auto Layout، الزوايا، الخطوط، القياسات، الأنماط، التأثيرات، وخصائص المكونات عند توافرها |
| `nodes[].propertyBindings` | لقطة ارتباطات كل خاصية قابلة للتحرير؛ **انسخ القيمة كلها** إلى `beforeBindings` |
| `nodes[].boundVariables` | ارتباطات المتغيرات على مستوى العنصر |
| `nodes[].textRuns` | نطاقات النص بـ UTF-16 مع الخط/الحجم/الألوان/الأنماط والارتباطات ذات الصلة |
| `nodes[].mainComponent` | معرّف ومفتاح واسم المكوّن الأصلي للنسخة، وعلامة remote إن توفرت |
| `nodes[].componentKey` | مفتاح المكوّن أو مجموعة المكونات عند توافره |
| `variables[]` | المتغيرات المشار إليها في الطبقات: المعرف والاسم والنوع والمجموعة والقيم حسب الوضع؛ `unavailable` إن تعذر الحصول عليه |

القيمة المختلطة `figma.mixed` تصدر بالشكل `{ "$mixed": true }`، ولا تقبل باعتبارها قيمة تعديل. هذا **جرد للتحرير الانتقائي، وليس نسخة احتياطية كاملة أو صيغة لإعادة بناء ملف Figma**. لا يشمل بايتات الصور ولا يدعم إنشاء الطبقات أو حذفها أو نقلها. تبقى التفاعلات والمكونات والأصول الموجودة في الملف كما هي.

`propertyBindings[property]` يتكون من `direct` لارتباط الخاصية (والزوايا الفردية عند طلب cornerRadius)، و`paintAliases` لمعرفات متغيرات الطلاء، و`text` لنطاقات النص وارتباطاتها. لا يحذف Codex الحقول الفارغة.

## صيغة ملف التعديلات

```json
{
  "schema": "codex-figma-patch",
  "version": 1,
  "workspaceId": "انسخه من التصدير",
  "exportId": "انسخه من آخر تصدير",
  "operations": [
    {
      "kind": "set",
      "nodeId": "1:1",
      "property": "itemSpacing",
      "before": 12,
      "beforeBindings": { "direct": {}, "paintAliases": [], "text": [] },
      "after": 20
    }
  ]
}
```

في كل عملية: `before` يساوي `nodes[].properties[property]` و`beforeBindings` يساوي `nodes[].propertyBindings[property]` في **نفس** التصدير. يعاد التحقق منهما مقابل التصميم الحي. العمليات الثلاث المدعومة:

| `kind` | الحقول الإضافية | السلوك |
|---|---|---|
| `set` | `after` | تغيير قيمة خاصية؛ تتجاوز العملية إذا كانت مرتبطة بمتغير، مع عرض السبب |
| `bind` | `variableId` كمعرّف موجود أو `null` | تغيير/فك ارتباط خاصية رقمية صراحة عبر `setBoundVariable`؛ لا يحتاج `after` |
| `paintBinding` | `paintIndex` بدءًا من 0، و`variableId` أو `null` | تغيير/فك متغير لون طلاء SOLID عبر `setBoundVariableForPaint`؛ الخاصية fills أو strokes، ولا يحتاج `after` |

في عمليات الربط تعرض المعاينة المتغير المقترح واسمه؛ القيمة المرئية النهائية يحددها وضع المتغير النشط في Figma. لا تنشئ الإضافة متغيرات ولا تستوردها من مكتبة عبر الشبكة. المتغير يجب أن يكون متاحًا لـ Plugin API في الملف.

مثال فك ربط المسافة صراحة (مع نسخ القيم الحقيقية من التصدير):

```json
{
  "kind": "bind",
  "nodeId": "1:1",
  "property": "itemSpacing",
  "before": 12,
  "beforeBindings": {
    "direct": { "itemSpacing": { "type": "VARIABLE_ALIAS", "id": "VariableID:1" } },
    "paintAliases": [],
    "text": []
  },
  "variableId": null
}
```

فك الارتباط يبقي القيمة المحلولة الحالية. لتغييرها بعد ذلك، طبّق فك الارتباط ثم صدّر مجددًا وأنشئ تعديل `set`. ترفض الإضافة تكرار الخاصية نفسها في دفعة واحدة، بما في ذلك الجمع بين `cornerRadius` وزواياه الفردية.

### الخصائص والقيم المقبولة

- النص: `characters`؛ ومحاذاة `textAlignHorizontal`: `LEFT/CENTER/RIGHT/JUSTIFIED`؛ ومحاذاة `textAlignVertical`: `TOP/CENTER/BOTTOM`.
- الألوان: `fills/strokes` كمصفوفة طلاءات SOLID من التصدير مع تغيير `color` و/أو `opacity` فقط. حافظ على العدد وكل الحقول الأخرى. RGB والشفافية أرقام بين 0 و1. لا تغيّر gradients أو الصور بهذه النسخة.
- الزوايا: `cornerRadius/topLeftRadius/topRightRadius/bottomLeftRadius/bottomRightRadius`، أرقام غير سالبة. الربط الصريح يدعم الزوايا الفردية؛ لا يدعم shorthand `cornerRadius`.
- Auto Layout: `layoutMode` (`NONE/HORIZONTAL/VERTICAL`)، `layoutWrap` (`NO_WRAP/WRAP`)، `primaryAxisAlignItems` (`MIN/CENTER/MAX/SPACE_BETWEEN`)، `counterAxisAlignItems` (`MIN/CENTER/MAX/BASELINE`)، `counterAxisAlignContent` (`AUTO/SPACE_BETWEEN`).
- القياس: `primaryAxisSizingMode/counterAxisSizingMode` (`FIXED/AUTO`)، `layoutAlign` (`INHERIT/STRETCH/MIN/CENTER/MAX`)، `layoutPositioning` (`AUTO/ABSOLUTE`)، `layoutGrow` (0 أو 1).
- التباعد: `itemSpacing` (يقبل التداخل السالب)، `counterAxisSpacing/paddingLeft/paddingRight/paddingTop/paddingBottom` أرقام غير سالبة؛ و`opacity` بين 0 و1.
- `bind` يحتاج متغير `FLOAT` ويدعم الخصائص الرقمية السابقة عدا `layoutGrow` و`cornerRadius`. `paintBinding` يحتاج متغير `COLOR`. يجب أن يدعم نوع العنصر الخاصية أصلًا؛ بعض أوضاع Figma تفرض قيودًا إضافية، ويؤدي رفضها إلى استعادة الدفعة.

تغيير `layoutMode` أو القياس أو النص قد يحرك الأبناء أو يعيد قياس Auto Layout طبيعيًا. راجع النتيجة داخل Figma. لا تدعم هذه النسخة Grid أو تغيير الخط أو اتجاه النص كخاصية مستقلة؛ العربي يستخدم الخط والمحاذاة واتجاه النص الذي يديره Figma.

### الحفاظ على التنسيق والمكونات

لا تنشئ الإضافة طبقات بديلة، ولا تستدعي `detachInstance` أو تبدّل المكوّن الأصلي. تغييرات النص داخل instance تنشئ override عاديًا مع بقاء ارتباطه. الطبقات المقفلة أو ذات أب مقفل تمنع الدفعة. الأنماط المرتبطة بطلاءات الألوان تمنع تغيير الطلاء بدل فصل النمط ضمنيًا.

تحمّل الإضافة جميع الخطوط المستخدمة في عناصر النص المستهدفة قبل الكتابة. وجود خط مفقود أو فشل تحميله يوقف الدفعة. تغيير `characters` مدعوم للنص المتجانس التنسيق؛ **استبدال نص متعدد نطاقات التنسيق مرفوض** حتى لا يُسطح تنسيق الخطوط والألوان والروابط. لا تحوّل النص إلى outlines ولا تغيّر الخط العربي. يمكن تعديل محاذاة النص متعدد التنسيق مع تحميل خطوطه.

## مثال النص ومسافة القائمة

راجع [patch.example.json](./examples/patch.example.json): يغير نص `1:2` من «القائمة» إلى «أحدث إعلانات الإبل»، ومسافة Auto Layout في `1:1` من 12 إلى 20. يتوافق مع مقتطف [selection.example.json](./examples/selection.example.json). المعرفات تعليمية؛ استخدم دائمًا معرفات ولقطة تصدير تصميمك. لا تكفي إعادة تسمية المثال كي يصبح صالحًا لملفك.

## التراجع وفشل الدفعة

بعد كل القراءات وتحميل الخطوط والتحقق النهائي، تفصل الإضافة الدفعة بـ `figma.commitUndo()`، ثم تنفذ كل الكتابات متزامنة دون `await`، ثم تعتمد حد التراجع. لذلك تعكس خطوة Undo واحدة الدفعة مع قياسات Auto Layout وoverrides التابعة.

إذا رفض Figma كتابة في منتصف الدفعة، تعتمد الإضافة الجزء المنفذ ثم تستدعي `figma.triggerUndo()` لاستعادته، وتتحقق من القيم والتنسيق والارتباطات السابقة للعناصر المستهدفة. استخدام Undo الأصلي يحفظ تفاصيل لا يستعيدها تعيين قيم سطحي. إذا رفض أول setter دون أي تغير، لا تستدعي Undo حتى لا تلغي عملًا سابقًا. يظهر سبب الفشل بالعربية مع رسالة API الأصلية. إن تعذر تأكيد الاستعادة، تعرض رسالة صريحة للتوقف وفحص سجل Undo وإعادة التصدير؛ لا تدعي نجاح الاستعادة.

الإضافة لا تقفل الملف أمام مستخدمين آخرين؛ استخدم نسخة عمل مستقلة دون تحرير متزامن أثناء التطبيق. المعاينة لا تكتب إلى التصميم. إنشاء هوية النسخة عملية بيانات مستقلة قابلة للتراجع، وخارج دفعات تحرير الطبقات.

## الفحوص المحلية

من جذر المستودع، باستخدام Node.js الموجود على جهاز التطوير:

```powershell
node --check tools/figma-local-editor/code.js
node --test tools/figma-local-editor/test/plugin.test.cjs
```

تتحقق الاختبارات من JSON، وتحلل JavaScript المضمن في [ui.html](./ui.html)، وتحاكي التصدير والربط والتعارض قبل وبعد المعاينة وتحميل الخطوط وفشل منتصف الدفعة والتراجع، وتفحص منع الشبكة. لا تحتاج تنزيل حزم.

**لم تُشغّل الإضافة داخل Figma Desktop في جلسة التنفيذ**؛ لم توجد عملية Figma مفتوحة بنسخة عمل للاختبار. المحاكاة لا تثبت قبول manifest أو سلوك Undo أو تنزيل الملف أو الخطوط في Figma الحقيقي.

### اختبار قصير داخل نسخة العمل

1. استورد manifest وشغّل الإضافة. هيّئ هوية النسخة. حدد إطار Auto Layout رأسيًا يحوي نصًا عربيًا متجانسًا، ثم صدّر. تحقق من الملف المحفوظ وأسماء الطبقات وعلاقاتها وخط العربية وارتباطاتها.
2. اطلب من Codex ملفًا مثل المثال باستخدام التصدير الحقيقي. استورده وتحقق من القيمتين في الجدول، ثم طبّق. افحص النص والمسافة وبقاء معرفات العناصر وارتباط instance بالمكوّن، ثم أعد التركيز للوحة واضغط Ctrl+Z مرة واحدة: يجب استعادة التغييرين معًا.
3. صدّر واستورد ملفًا جديدًا ثم غيّر المسافة يدويًا **بعد المعاينة** واضغط تطبيق: يجب رفض الدفعة قبل تغيير النص. جرّب كذلك `workspaceId` مختلفًا وعنصرًا محذوفًا و`before` خاطئة في ملف تجريبي.
4. اربط مسافة بمتغير ثم صدّر. عملية set عليها يجب أن تظهر «متجاوز». اطلب bind صريحًا إلى متغير FLOAT موجود أو null، وتحقق من الربط ثم Undo. كرر مع لون SOLID ومتغير COLOR وpaintBinding.
5. جرّب نصًا متعدد التنسيق: تغيير كامل characters يجب أن يرفض، والمحاذاة يجب أن تبقي تنسيق النطاقات. جرّب خطًا غير متاح: يجب أن يفشل التحضير قبل أي تعديل.
6. لاختبار فشل منتصف الدفعة بشكل حتمي، على نسخة **من مجلد الإضافة** استبدل مؤقتًا في code.js السطر `attempted = true;` بالسطرين `if (attempted) throw new Error("اختبار فشل منتصف الدفعة");` ثم `attempted = true;`. أعد تحميل الإضافة، صدّر ملفًا جديدًا واستورد دفعة بعمليتين مختلفتين: يجب تنفيذ الأولى ثم استعادتها مع رسالة تحقق الاستعادة وبقاء الثانية دون تغيير. أعد الكود الأصلي قبل الاستخدام، أو احذف نسخة الاختبار. اختبر Undo أيضًا مع بقاء النافذة مفتوحة وبعد إغلاقها.

احتفظ بنسخة العمل الأصلية قبل اعتماد الإضافة في تعديلات واسعة، إلى أن تُكمل اختبارات Desktop السابقة.
